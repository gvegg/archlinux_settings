# GRUB: как устроена тема noto_menu

Эта тема — не картинка на весь экран, а набор из трёх независимых слоёв:

1. **фон** — просто чёрный цвет, без изображения;
2. **три белые плашки** — 9-patch PNG, которые GRUB растягивает под пункты;
3. **три подписи** — RGBA-PNG с настоящим сглаживанием, лежат поверх плашек.

Сверху ничего нет: ни заголовка «GNU GRUB», ни номеров, ни фоновых волн.

---

## 1. Визуальные параметры

| Параметр | Значение | Где задано |
|---|---|---|
| Режим | 1600×900×32 | `/etc/default/grub`, `GRUB_GFXMODE` |
| Фон | `#000000`, без картинки | `theme.txt`, `desktop-color` |
| Плашка | 184×44 px, радиус 16, зазор 10 | `theme.txt` + 9-patch PNG |
| Позиция меню | `left=708`, `top=374`, `width=184`, `height=152` | `theme.txt`, `boot_menu` |
| Заливка плашки | `#ffffff` | `plate_*.png` |
| Рамка обычной | `#dedede`, 2 px | `plate_*.png` |
| Рамка выбранной | `#007aff`, 2 px | `plate_hi_*.png` |
| Подписи | `#2b2b2b`, Noto Sans Regular 24 px | `caption_*.png` |
| Шрифт терминала | Noto Sans Regular 24 (pf2) | `NotoSans-Regular-24.pf2` |
| Терминал | чёрный, border 0 | `theme.txt` |

Почему 184 px: самая длинная подпись «Arch Linux» при 24 px занимает
119 px; по 32 px поля с каждой стороны: `119 + 64 = 183`, округлено до
чётного 184.

Почему `top=374`: три плашки по 44 px и два зазора по 10 px дают
`3×44 + 2×10 = 152`; `(900 − 152) / 2 = 374`.

---

## 2. `theme.txt`: верхний уровень

В GRUB верхнеуровневые свойства темы должны быть **в кавычках**:

```text
desktop-color: "#000000"
terminal-border: "0"
```

Если написать `terminal-border: 0` без кавычек, GRUB может выдать
`property value invalid; enclose literal values in quotes` и уйти в
текстовый режим. Это одна из самых частых ловушек.

### Почему `desktop-color`, а не `desktop-image`

`desktop-image` рисует картинку на весь экран. `desktop-color` задаёт
однотонный фон. Мы используем второе:

- нет файла фона — меньше темы и нет проблем с масштабированием;
- чёрный фон совпадает с чёрным фоном Plymouth, поэтому переход
  GRUB → заставка не даёт белой вспышки;
- не нужна лицензия CC BY-SA старой картинки.

`desktop-image` в `theme.txt` **отсутствует**. Если он появится снова,
`desktop-color` может быть проигнорирован.

---

## 3. Почему подписи — PNG, а не текст GRUB

GRUB-шрифты `.pf2` — это bitmap-шрифты **без сглаживания**. `grub-mkfont`
не умеет grayscale-AA. Текст, нарисованный самим GRUB, выглядит зубчатым,
особенно на белых плашках.

Поэтому:

- подписи отрендерены обычным TTF (Noto Sans) через FreeType/Pillow в RGBA;
- каждая PNG обрезана по чернилам, с прозрачным фоном;
- GRUB рисует PNG с альфа-блендингом поверх плашек;
- pf2-шрифт всё равно нужен: он используется для терминала и скрытого
  текста `boot_menu` (текст белый на белой плашке, поэтому не виден).

Подписи лежат в `theme.txt` блоками `+ image`:

```text
+ image {
  file = "caption_0.png"
  left = 741
  top = 387
  width = 119
  height = 18
}
```

Координаты — абсолютные для 1600×900. `left` центрирует подпись по
плашке, `top` — по вертикали.

### Порядок отрисовки

GRUB рисует компоненты **в обратном порядке файла**: кто позже в
`theme.txt`, тот ниже. Поэтому `+ image` с подписями стоят **до**
`+ boot_menu`. Если поставить их после, плашки закроют текст.

## 4. 9-patch плашки

Плашки — не один PNG, а 18 маленьких файлов:

- `plate_c.png`, `plate_n.png`, `plate_s.png`, `plate_e.png`, `plate_w.png`,
  `plate_nw.png`, `plate_ne.png`, `plate_sw.png`, `plate_se.png` — обычная;
- `plate_hi_*` — выбранная, с синей рамкой.

GRUB собирает из них прямоугольник:

- углы `nw/ne/sw/se` не растягиваются;
- `n/s` тянутся по ширине;
- `e/w` тянутся по высоте;
- `c` — центр.

Это позволяет иметь маленькие PNG и получать плашку любого размера с
гладкими углами.

### Главная ловушка: `item_height` — не высота плашки

9-patch в GRUB добавляет пады сверху и снизу, равные радиусу скругления
(16 px). Поэтому:

```text
видимая высота = item_height + 2 × radius
44 = 12 + 2 × 16
```

В `theme.txt`:

```text
item_height = 12
item_spacing = 42
```

Шаг строк:

```text
item_height + item_spacing = 12 + 42 = 54
54 = 44 (плашка) + 10 (зазор)
```

Если поставить `item_height = 44`, плашки станут 76 px и наедут друг на
друга. Если `item_spacing` не 42, изменится зазор.

### Почему рамка «внутри»

В генераторе `make_plates.py` рамка рисуется внутри радиуса, а не снаружи.
Так 9-patch не выходит за заявленные 184×44 и не перекрывает соседние
плашки.

## 5. Шрифт pf2

`NotoSans-Regular-24.pf2` собран так:

```bash
grub-mkfont -n "Noto Sans" -s 24 \
  -o NotoSans-Regular-24.pf2 \
  /usr/share/fonts/noto/NotoSans-Regular.ttf
```

Важно:

- имя файла — **без пробелов** (`NotoSans-Regular-24.pf2`), иначе
  `loadfont` в конфиге ломается;
- внутреннее имя должно совпадать с `theme.txt`: `Noto Sans Regular 24`;
- `-n "Noto Sans"` + `-s 24` даёт именно `Noto Sans Regular 24`;
  `-n "Noto Sans Regular"` даст двойной стиль и не совпадёт.

В теме:

```text
terminal-font: "Noto Sans Regular 24"
item_font = "Noto Sans Regular 24"
selected_item_font = "Noto Sans Regular 24"
```

`item_font` задаёт размер pf2 для терминала и скрытого текста меню.
Подписи-картинки имеют свой размер (24 px), он задаётся при генерации.

---

## 6. `terminal-border: "0"` — почему обязательно

Когда GRUB выбирает пункт и передаёт управление ядру, он вызывает
`grub_cls()`. Тот очищает только текстовое поле `gfxterm`, но **не**
перерисовывает полосу `terminal-border` по краям экрана. Если border
ненулевой, на чёрном фоне остаётся светлая рамка, которая висит до тех
пор, пока экран не перехватит `fbcon`/Plymouth (иногда до 10–15 секунд).

С `terminal-border: "0"` текстовое поле занимает весь экран, и очистка
гасит его целиком в чёрный. Поэтому рамки нет.

## 7. `GRUB_GFXMODE` и `GRUB_GFXPAYLOAD_LINUX`

```text
GRUB_GFXMODE=1600x900x32
GRUB_GFXPAYLOAD_LINUX=keep
```

- `GRUB_GFXMODE` задаёт режим, в котором GRUB рисует меню и тему.
- `GRUB_GFXPAYLOAD_LINUX=keep` просит не менять видеорежим при передаче
  ядру. Это уменьшает мигание/чёрную вспышку между меню и Plymouth.
- `GRUB_TIMEOUT=-1` — не выбирать пункт автоматически, ждать пользователя.
- `GRUB_TIMEOUT_STYLE=menu` — показывать меню, а не скрывать его.

Тема пиксельная: координаты 708/374 и PNG рассчитаны на 1600×900. Если
GRUB не может включить этот режим и выберет другой, плашки могут сместиться.
См. [`INSTALL.md`](INSTALL.md), раздел «Другое разрешение».

## 8. Меню из трёх пунктов (`40_custom`)

Тема сама по себе не ограничивает число пунктов. Ровно три пункта — это
отдельный статический `/etc/grub.d/40_custom`, шаблон лежит в
[`../grub/40_custom.example`](../grub/40_custom.example).

### Почему статическое меню

- ровно три плашки, без «Advanced options for Arch Linux»;
- предсказуемая командная строка ядра;
- никаких автоматических записей, которые могут изменить вид;
- Windows запускается через UEFI BootNext, не через цепочку разделов.

### UUID и пути

`search --fs-uuid --set=root __BOOT_UUID__` выбирает загрузочный раздел.
Дальше пути `/vmlinuz-linux` и `/initramfs-linux.img` считаются от него.

- `/boot` отдельный → UUID `/boot`, пути `/vmlinuz-linux`;
- `/boot` внутри корня → UUID корня, пути `/boot/vmlinuz-linux`.

`root=UUID=__ROOT_UUID__` — это UUID корня, он передаётся ядру.

### UEFI и BIOS

Шаблон рассчитан на UEFI с FAT `/boot`:

```text
insmod part_gpt
insmod fat
```

Для BIOS/MBR обычно нужны `part_msdos` и `ext2` (или `ext4`), а `fwsetup`
недоступен. Проверь свою систему и убери лишнее.

### Windows через BootNext

```text
menuentry 'Windows' {
  if bootnext 0001; then
    reboot
  fi
}
```

`bootnext 0001` не читает и не пишет разделы Windows. Он только говорит
прошивке: «следующая загрузка — Boot0001». Номер надо взять из
`efibootmgr -v`; `0001` — пример. Если Windows нет, пункт удаляется.
Если `bootnext` не сработал, GRUB просто не перезагрузится; проверь номер.

### UEFI BIOS

```text
menuentry 'UEFI BIOS' {
  fwsetup
}
```

Работает только на UEFI и не на всех прошивках. На BIOS-системе пункт
нужно удалить.

### Тишина и splash

В ручном `menuentry` **не работает** `GRUB_CMDLINE_LINUX_DEFAULT`.
Поэтому параметры ядра прописаны прямо в строке `linux`:

```text
quiet loglevel=0 systemd.show_status=no udev.log_level=0 splash
```

- `splash` включает Plymouth;
- `quiet`/`loglevel`/`show_status`/`udev.log_level` убирают текст;
- `root=UUID=...` и `rw` обязательны.

Если убрать `splash`, Plymouth не запустится. Если убрать `quiet`, будет
видна диагностика — это полезно при отладке.

### Генераторы

Чтобы не было лишних пунктов, отключаются:

```text
/etc/grub.d/10_linux
/etc/grub.d/30_uefi-firmware
/etc/grub.d/31_efi_bootnext
```

через `chmod -x`. Файлы остаются на диске; вернуть можно `chmod +x`.
После изменения — `grub-mkconfig -o /boot/grub/grub.cfg`.

Не запускай `grub-install`: он не нужен для темы и меню.

## 9. Установка и проверка

```bash
sudo bash grub/install-theme.sh
```

Скрипт копирует тему, выставляет визуальные ключи и делает
`grub-mkconfig`. Он **не** трогает `40_custom` и генераторы.

Проверка:

```bash
grep -E 'desktop-color|desktop-image' /boot/grub/themes/noto_menu/theme.txt
grep -E 'GRUB_THEME|GRUB_GFXMODE|GRUB_GFXPAYLOAD_LINUX' /etc/default/grub
grep -n 'noto_menu' /boot/grub/grub.cfg
```

Если меню текстовое:

1. проверь, что `theme.txt` существует и в нём нет невалидных свойств
   без кавычек;
2. проверь `GRUB_THEME` и `GRUB_GFXMODE`;
3. снова `grub-mkconfig`;
4. см. [`TROUBLESHOOTING.md`](TROUBLESHOOTING.md).

## 10. Почему не оставлен старый фон

Старая тема использовала белую картинку с волнами. Она:

- требовала отдельный PNG 1600×900;
- давала белую вспышку при переходе в Plymouth;
- тянула лицензию CC BY-SA;
- не давала «постоянно чёрный» фон, который просил владелец.

Сейчас фон — `desktop-color: "#000000"`. Плашки остались белыми, потому
что на чёрном они дают нужный контраст и сохраняют утверждённую геометрию.
